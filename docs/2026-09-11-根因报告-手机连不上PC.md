## 一、手机连不上 PC —— 根因已修复并实测通过

### 根因

`src/rendezvous_mediator.rs` 用 `crate::platform::is_installed()` 作为 **LAN 发现监听（UDP 21119）的启动闸门**。

该函数在 Windows 上判断的是「注册表 `InstallLocation` 指向的 `LDesk.exe` 是否存在」，
找不到注册表项时回退到默认路径 `C:\Program Files\LDesk`。而**便携版 / 免安装运行**
（解压到 `%LOCALAPPDATA%\LDesk\runtime\<pkgid>\`）两条路径都不存在，
于是 `is_installed()` 恒为 `false` → **永远不 bind 21119**。

因果链：

1. 手机在同网段广播 LAN ping（目标 21119）
2. PC 没有监听 → **无人应答**
3. 手机拿不到 PC 的局域网地址 → `LanPeers` 里永远没有 PC
4. PC 端三条直连路径全部落空：`direct_peer_hosts`（显式 IP）→ `lan_peer_hosts`（LAN 缓存）→
   连接前补发现 `discover_lan_first_within`
5. 只能回落信令链路；而手机端经 WebSocket 注册后 `socket_addr` 是 `公网IP:0`，
   TCP 打洞在协议层就不可用 → **必然连不上**

### 改前取证

|---|---|---|
| PC `192.168.31.42` (pid 13656) | 只有 `TCP 21118` + 一个临时 UDP，**无 21119** | **无应答** |
| OPPO PFUM10 `192.168.31.70` | `UDP 21119` 正常 | PONG `id=905885` |

日志侧的不对称亦吻合：PC 有 7 条 `DIRECT_CONNECT`（PC→手机，手机在听），
**手机→PC 一条都没有**。

### 顺带修复

- `src/lan.rs`：新增**单播网段扫描**。华为 / 荣耀等 ROM 会在 Wi-Fi 驱动层丢弃非单播报文，
  这类设备永远不回广播，但对单播 100% 响应。扫描收敛到 /24、上限 254 主机、
  跳过 VPN/虚拟机网卡；周期性发现按 45s 限频，连接前补发现不限频。
  另为 `start_listening` 增加绑定退避重试（10 × 500ms）。
- `src/client.rs`：连接前无显式 IP 且 LAN 缓存为空时，现场补一轮发现（1500ms）；
  `DIRECT_CONNECT` 日志增加 `kind=` 字段。
- `.github/workflows/build-exe.yml`：第 18 步 `rcedit` 因不在 PATH 报 exit 127，
  而 x64 分支没有 `|| true`，导致 2.2.33 发布构建（run #960）整体失败、产物上传被 skip。
  已改为显式补 PATH + 不可用时告警放行。

### 已排除的可能（均有实测依据）

- Windows 防火墙拦截：`netsh advfirewall show allprofiles state` 三个配置文件**全部关闭**
- `enable-lan-discovery` 默认关闭：`option2bool` 对 `enable-` 前缀默认 `true`
- FFI ABI 不兼容：`bridge_generated.rs` / `flutter_ffi.rs` / `ui_interface.rs`
  自 `b0b869a`(2.2.25) 起未改动，故 2.2.30 的 Flutter 侧配新 DLL 安全
- 中继服务器被改坏：**未改动**。PC 端 `rendezvous peer registration acknowledged` 持续正常

## 二、rev.dicad.cn 证书不匹配 —— 已定位，待确认后修复

### 症状

移动端连 `wss://rev.dicad.cn/ws/id` 报：

```
verifier.rs:136 Both primary and fallback verifiers failed to verify server certificate,
  primary: InvalidCertificate(NotValidForNameContext {
    expected: DnsName("rev.dicad.cn"), presented: ["DnsName(\"dicad.cn\")"] }),
  fallback: InvalidCertificate(Revoked)
websocket.rs:129 WebSocket connection with Rustls-tls failed, retry accepting invalid certs
```

最终因"接受无效证书"兜底**仍能连上**，属降级可用，非硬断。

### 取证

| 项 | 事实 |
|---|---|
| 443 实际服务方 | 1Panel 的 OpenResty 容器 `1Panel-openresty-uGYp`（主机 nginx **未运行**，`systemctl is-active nginx` = failed） |
| 命中哪个 server 块 | `/opt/1panel/www/conf.d/dicad.cn.conf`，`server_name dicad.cn rev.dicad.cn`（第 4 行，**手工添加**，不归 1Panel 管） |
| 该块用的证书 | `/www/sites/dicad.cn/ssl/fullchain.pem` = `CN=dicad.cn`，SAN **仅** `DNS:dicad.cn`（notBefore 2026-09-10 10:04:03 UTC） |
| 1Panel 站点 | 只有 3 个：`dicad.cn`(ssl_id 5)、`tk.dicad.cn`(4)、`api.dicad.cn`(7)。**没有 rev.dicad.cn 网站** |
| 用户申请的 rev 证书 | `website_ssls` id=6：`rev.dicad.cn`，provider=http，**status=ready**，**auto_renew=1**，2026-12-09 到期，pem 4807B |
| 该证书为何没生效 | 没有站点承载它 → 从未写入任何站点 ssl 目录 → 磁盘上不存在 rev 的 PEM |
| 未被使用的正确配置 | `/etc/nginx/conf.d/rev-dicad-cn.conf`（含 `/ws/id`→21118、`/ws/relay`→21119）+ `/etc/letsencrypt/live/rev.dicad.cn/`（8/28 签发，SAN 正确）—— 但主机 nginx 没运行 |
| 故障形态迁移 | 9/10 01:38 是 **DNS 解析失败**；9/11 03:41 起才变成 **证书 SAN 不匹配** |

9/10 晚间 1Panel 的签发记录：

```
19:02:34  申请 [dicad.cn]     证书成功   (http-01, 仅 dicad.cn)
19:03:14  申请 [rev.dicad.cn] 证书成功   (http-01)   <- 就是 id=6
19:07:54  [dicad.cn]          DNS-01 TXT record mismatch 失败
19:08:09  [rev.dicad.cn]      DNS-01 TXT record mismatch 失败
```

### 隐患

`dicad.cn.conf` 里那行手工 `rev.dicad.cn` 是**裸配置**：1Panel 的 `website_domains`
里并没有这条域名，因此**下次 1Panel 重新生成该站点配置时这行会消失**，
届时 rev.dicad.cn 的 `/ws/id`、`/ws/relay` 反代会一起丢掉。

### 修复方案（只新增文件，不改动任何现有配置）

1. 从 `website_ssls` id=6 导出 PEM 与私钥，写入
   `/opt/1panel/www/sites/rev.dicad.cn/ssl/{fullchain.pem,privkey.pem}`
   （容器内路径 `/www/sites/rev.dicad.cn/ssl/`）
2. 新增 `/opt/1panel/www/conf.d/rev.dicad.cn.conf`
   （→ 容器 `/usr/local/openresty/nginx/conf/conf.d/`，被 `nginx.conf` 的
   `include .../conf.d/*.conf` 加载）：
   - `server_name rev.dicad.cn`，80 跳 443 + ACME challenge
   - 443 使用上述证书
   - `/ws/id` → `http://127.0.0.1:21118`、`/ws/relay` → `http://127.0.0.1:21119`
     （含 `Upgrade`/`Connection` 头 + 86400s 超时）
3. `docker exec 1Panel-openresty-uGYp nginx -t` 校验通过才 reload；
   不通过立即删除新文件回滚
4. **续期同步**：装一个 root cron，每天从 `website_ssls` id=6 读 PEM，
   内容有变化才覆盖并 reload —— 这样 1Panel 自动续期后证书自动跟上，
   不依赖 1Panel 未文档化的 `push_dir` 行为
5. 验证：`openssl s_client -servername rev.dicad.cn -connect rev.dicad.cn:443`
   应显示 `CN=rev.dicad.cn`；再从两台真机复测 WS

> 因涉及生产 HTTPS（与 `dicad.cn` 共用同一 OpenResty），执行前需确认。
