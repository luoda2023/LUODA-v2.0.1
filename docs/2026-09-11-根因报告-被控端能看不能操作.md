# 根因报告：手机作为被控端「能看不能操作」

日期：2026-09-11
现象（用户原话）：*「能看但无法操作」* —— 手机→手机、PC→手机两个方向都是：画面正常，鼠标/键盘完全无效。
用户诉求：*「输入服务 是应该自动默认保存开通的。只要第一次安装后，开通了就保存好了。」*

现场：OPPO PFUM10 `7358bbbb`、华为 ABR-AL80 `GNH0222922000982`，两台均 **LDesk 2.2.40**（`versionCode=2957`，今日 16:28 原地升级）。

---

## 结论速览

| # | 根因 | 层面 | 状态 |
|---|---|---|---|
| A | 两台手机的**「LDesk Input」无障碍服务在系统层是关闭的** —— 没有它，Android 端不可能注入任何鼠标/键盘事件 | 设备 / 系统授权 | 已定位（Android 平台约束，见「无法自动开启」） |
| B | 输入事件在 `InputService.ctx == null` 时被 `?.` **静默吞掉**：无日志、无提示、主控端也无从得知 | Android 代码 | **已修复** |
| C | 首次安装引导流程**不含无障碍这一步**，冷启动又走静默路径 → 用户全程没被引导过要开它 | Flutter 代码 | **已修复** |
| D | 「输入」开关在 `_inputOk=false` 但系统授权已在时**点了没反应**（漏收 `on_state_changed` 时的死角） | Flutter 代码 | **已修复** |

A 是直接原因，B/C/D 是「为什么一直没人发现、也没法一键恢复」。

---

## 根因 A：无障碍服务没开，且 App 无法自己开

### 取证（决定性）

```bash
ADB="G:/Android/sdk/platform-tools/adb.exe"
"$ADB" -s 7358bbbb            shell settings get secure enabled_accessibility_services
"$ADB" -s GNH0222922000982    shell settings get secure enabled_accessibility_services
"$ADB" -s <device>            shell dumpsys accessibility | grep -m1 'Enabled services'
```

两台的结果都只有厂商自带服务：

```
OPPO  : com.oplus.ocar/com.oplus.xgui.core.service.XGuiAccessibilityService
华为  : com.huawei.distributedpasteboard/com.huawei.dragdrop.service.DragDropAccessibilityService
```

`dumpsys accessibility` 的 `Enabled services:` 段同样**不含** `com.luoda.remote/.InputService`。
注意 `dumpsys` 里能搜到 `com.luoda.remote/.InputService` 的条目 —— 那是「系统认识这个服务」（清单声明正确、`capabilities:[CAN_RETRIEVE_WINDOW_CONTENT, CAN_PERFORM_GESTURES]`），**不等于已启用**；判据要看 `enabled_accessibility_services` / `Enabled services`。

### 为什么 App 开不了

Android 明确禁止第三方应用自行启用无障碍服务：

```bash
"$ADB" -s 7358bbbb shell settings put secure enabled_accessibility_services "…:com.luoda.remote/com.luoda.remote.InputService"
# java.lang.SecurityException: Permission denial: writing to settings requires:
# android.permission.WRITE_SECURE_SETTINGS
```

连 adb shell 都被拒（`WRITE_SECURE_SETTINGS` 拿不到），App 侧只有 `ACTION_ACCESSIBILITY_DETAILS_SETTINGS` 这一条「跳到开关页」的路。

### 为什么它会丢

无障碍授权存在 `Settings.Secure` 里、以组件名为键，**App 无法保证它持久**：

* 卸载重装必然丢失（升级覆盖安装通常保留）；
* 国产 ROM（MIUI / EMUI / ColorOS）在**应用更新后、以及被「强制停止」后**会关掉第三方无障碍服务 —— 本轮排障过程中大量使用 `am force-stop com.luoda.remote`，与「服务被关」直接吻合；
* 用户在 App 内把「输入」开关关掉时，代码会调 `disableSelf()`（= 真正撤销系统授权），要再开必须回系统设置。

**结论：所谓「自动默认开通」在 Android 上做不到。能做到的是 —— 首次安装引导一次、丢了立刻发现、一键恢复。**

## 根因 B：输入被静默丢弃

`flutter/android/app/src/main/kotlin/com/luoda/remote/MainService.kt`：

```kotlin
fun rustPointerInput(kind: Int, mask: Int, x: Int, y: Int) {
    …
    when (kind) {
        0 -> { InputService.ctx?.onTouchInput(mask, x, y) }   // ctx == null → 什么都不发生
        1 -> { InputService.ctx?.onMouseInput(mask, x, y) }
        else -> {}
    }
}

fun rustKeyEventInput(input: ByteArray) {
    InputService.ctx?.onKeyEvent(input)                       // 同上
}
```

`InputService.ctx` 只在 `onServiceConnected()` 置位、`onDestroy()` / `onUnbind()` 清空（`InputService.isOpen = ctx != null`，状态本身是准的）。
服务没开 ⇒ `ctx == null` ⇒ 每一个事件都被 `?.` 吃掉，**没有一行日志、没有任何界面反馈**。主控端看到的是「画面在动、点哪都不动」。
这正是「能看不能操作」的全部观感来源。

> 旁证：`flutter/lib/models/server_model.dart` 在移动端启动时**强制** `enable-keyboard = 'Y'`，界面上「输入」看起来是开的，进一步掩盖了问题。

## 根因 C：首次安装引导不含无障碍

`flutter/lib/mobile/pages/home_page.dart` 里 `_firstRunPermissionFlow` 原本只有一步：

```dart
_firstRunPermissionFlow = FirstRunPermissionFlow(
  [ () => _requestStandardPermissionsBatch() ],
  stepNames: ['standard_permissions'],
```

而冷启动在 `_canStartQuietly()` 命中时**完全静默**（注释写明「accessibility is deliberately not re-checked here」）。
两条路叠起来的结果：**用户从头到尾没有任何一个时刻被提示「要开输入服务」**，只能自己摸到「共享屏幕」页去点那个开关。

## 根因 D：开关在特定状态下点了没反应

`server_model.dart` 的 `toggleInput()`：

```dart
if (_inputOk) {
  parent.target?.invokeMethod("stop_input");
  bind.mainSetOption(key: kOptionEnableKeyboard, value: 'N');
} else if (parent.target != null) {
  final granted = await AndroidPermissionManager.checkAccessibility();
  if (!granted) { showToast(…); await …startAction(kActionAccessibilityDetailsSettings); }
  // granted == true 时：什么都不做 ← 死角
}
```

若服务已连上但 UI 漏收了 `on_state_changed`（例如服务在 App 后台时被系统重启），`_inputOk` 会停在 false，
此时点开关走 `granted == true` 分支 → **什么都不发生**，用户以为「开关坏了」。

## 修复

| 文件 | 改动 |
|---|---|
| `MainService.kt` | 新增 `inputServiceOrNull()` 取代两处 `InputService.ctx?.`：`ctx == null` 时限流（5s 一条）打 `remote input dropped: accessibility service is not enabled`，并**每轮故障一次性**通知 Flutter `on_input_unavailable`；服务恢复后自动收尾 |
| `MainService.kt` | 新增 `notifyInputServiceMissing()`：发一条独立高优先级通知（`INPUT_NOTIFY_ID = 2`，用**新建 builder** 以免污染前台服务通知），点击直达系统无障碍列表。被控时会话里 App 几乎总在后台，Flutter 弹窗看不见，通知才看得见 |
| `server_page.dart` | 处理 `on_input_unavailable` → `showInputUnavailableNotice()`：弹一次说明框（复用 `android_input_permission_tip1` 文案），按钮直达 LUODA Input 开关；用 `whenComplete` 复位防重入标志 —— 否则一次 `dialogManager.dismissAll()` 就会让它永久抑制 |
| `home_page.dart` | 首次安装引导加第二步 `input_service`：先弹说明，再跳转 `kActionAccessibilityDetailsSettings`，并在系统页轮询回查（最多 20s，成功即返回） |
| `server_model.dart` | `toggleInput()` 的 `granted == true` 分支补上「重新同步」：置 `enable-keyboard = 'Y'` + `_inputOk = true` + `notifyListeners()`，消掉「点了没反应」 |

## 复验方法

**A/B/D 的静态判据**

```bash
ADB="G:/Android/sdk/platform-tools/adb.exe"
"$ADB" -s <device> shell settings get secure enabled_accessibility_services   # 应含 com.luoda.remote/.InputService
"$ADB" -s <device> shell dumpsys accessibility | grep -m1 'Enabled services'  # 同上
```

**B 的运行时判据**（装新包后，在输入服务关闭的状态下从对端连接并操作）

```bash
"$ADB" -s <device> logcat -d -v time | grep -E "remote input dropped|on_input_unavailable"
```

预期：出现限流警告；手机端弹出说明框 / 通知栏出现「LDesk」通知，点击直达无障碍列表。
把输入服务打开后，`remote input dropped` 停止，通知自动消失（`notificationManager.cancel(2)`）。

**C 的判据**：全新安装（先清掉 `android-first-run-authorization-v2` 等标记）后冷启动，
应在标准权限之后弹出「开启输入服务」说明框；日志出现
`first-run step 2/2 (input_service): granted`。

## 约束与遗留（重要）

1. **「自动默认开通」不可实现**：Android 不允许第三方 App 启用无障碍服务，adb 也因缺 `WRITE_SECURE_SETTINGS` 被拒。
   本次落地的是「首次安装引导一次 + 丢失后立刻发现并一键恢复」。
2. **`disableSelf()` 仍然保留**：App 内关掉「输入」开关 = 真正撤销系统授权，需回系统设置再开。
   若要改成「关开关只停用、保留授权」，需连带改 Rust：
   `src/server/connection.rs` 的 Android 分支目前**不检查** `peer_keyboard_enabled()`（桌面分支检查），
   所以现在**只有 `disableSelf()` 能让开关真正生效**；另外 `enable-keyboard` 的变更也不会同步到已建立的连接。
3. **Kotlin 侧未本地编译**：本机 `~/.gradle/caches/journal-1/journal-1.lock` 被其他 java 进程占用
   （Gradle 报 `FileNotFoundException … 拒绝访问`），沙箱内外均无法启动构建；改动已逐行复核 + 符号交叉验证，交由 CI 编译。
4. Dart 侧：`dart analyze lib/mobile/pages/server_page.dart lib/mobile/pages/home_page.dart lib/models/server_model.dart`
   → `No issues found!`
